# Onboarding Experience Design

**Date:** 2026-08-24
**Status:** Approved for planning

## Purpose

Make the path from downloading the DMG to working in a first folder —
and coming back the next day — frictionless. No wizards, no coach
marks, no accounts: the onboarding is a dressed installer, a welcome
document that demonstrates the product by being editable, correct
macOS integration, and memory of where you work.

## Components

### 1. DMG dressing — `scripts/bundle_macos.sh`, `assets/dmg/`

The DMG opens as a designed window: app icon left, `/Applications`
symlink right, background image with an arrow and "drag to install".

- Staging dir gains: `Applications` symlink, `.background/bg.png`
  (generated by a new `scripts/make_dmg_bg.py`, pure Python like
  `make_icon.py`: 660×420 @2x, Jackfruit paper background, wordmark,
  arrow), and a committed `assets/dmg/DS_Store` copied in as
  `.DS_Store`.
- The `DS_Store` is authored once locally (mount a RW image, arrange
  via Finder/osascript, harvest the file, commit it); CI just copies
  it — no Finder scripting on runners.
- Volume name stays `SuperMD`.

### 2. Move to Applications — `src/main.rs` (+ small helper module)

On launch, if the bundle is running from the DMG or a translocated
path, offer to install:

- Detection (`src/install.rs`): executable path contains `/Volumes/`
  or `/AppTranslocation/`; also expose `bundle_path()` (walk up from
  `current_exe` to `.app`). Pure predicate `needs_install(path) ->
  bool` is unit-tested.
- Offer: a slim banner rendered at the top of the workspace (not a
  modal): "SuperMD is running from the disk image — Move to
  Applications?" with [Move] and [Not now]. "Not now" dismisses for
  the session.
- Move: `ditto <bundle> /Applications/SuperMD.app`, then
  `open /Applications/SuperMD.app` and `cx.quit()`. Errors (e.g. no
  write permission) surface in the banner text; never crash.

### 3. Welcome tour document — `WELCOME.md`

Rewritten from the internal phase table into a product tour that
teaches by doing, in this order: "this page is editable" → click a
checkbox → click into **bold** to reveal markers → a small live table
→ a code fence → ⌘P / ⌘⇧F / ⌘⇧D / ⌘T one-liners → "Open a folder
(⌘O) to make this yours". Voice: short, warm, zero marketing. The
development-phase table moves to `docs/HISTORY.md`.

### 4. File associations & open events — `scripts/bundle_macos.sh`, `src/main.rs`

- `Info.plist` gains `CFBundleDocumentTypes`: Editor role for
  `net.daringfireball.markdown` + extensions (md, markdown, mdown,
  mdx), Alternate-Editor role for `public.plain-text` and
  `public.folder`. This enables double-click open, "Open With",
  Dock-icon drops, and `open -a SuperMD <path>`.
- `Application::on_open_urls` (registered before `run`): parse
  `file://` URLs, forward to the workspace — folders open as
  workspace root, files as permanent tabs. Arriving before the window
  exists (cold launch) is handled by stashing into the same
  `Option<PathBuf>` slot the CLI arg uses today (first path wins as
  the launch target; the rest open as tabs after window creation).

### 5. Recents & reopen-last — `src/settings.rs`, `src/workspace.rs`, `src/main.rs`

Settings additions (all `#[serde(default)]`, existing files stay
valid):

```toml
reopen_last = true          # default
recent_workspaces = ["/abs/path", …]   # most recent first, max 8
```

- `Settings::note_workspace(&mut self, path)` (pure, tested):
  dedupe + push-front + truncate to 8.
- Every successful folder open records + saves settings.
- Launch with no target: if `reopen_last` and the most recent path
  still exists → open it; else the welcome/empty state (first run
  unchanged).
- Empty-state sidebar shows up to 5 recents as clickable rows
  (folder name strong, dimmed parent path) under the "Open Folder…"
  button.
- File → Open Recent submenu built from settings at startup (static
  per-launch; the in-app empty state is the live surface).
  Menu items dispatch `OpenRecent(usize)` — an action carrying the
  index into the startup snapshot.

### 6. Drag & drop — `src/workspace.rs`

The workspace root accepts Finder drags (`on_drop::<ExternalPaths>`):
folders → `open_path` (workspace root), files → permanent tabs. While
a drag hovers, the window shows a subtle accent-tinted inset border as
the drop affordance (`.drag_over::<ExternalPaths>` styling). The
empty-state sidebar's hint line becomes "…or drop a folder here".

## Error handling

- Move-to-Applications failures render in the banner; the app keeps
  running from wherever it is.
- Open-URL events for nonexistent paths are ignored silently.
- Recents entries whose paths no longer exist are skipped at render
  and pruned on the next save.

## Testing

- `install.rs`: `needs_install` path predicates.
- `settings.rs`: `note_workspace` dedupe/order/cap; parsing files
  with and without the new keys.
- Welcome/DMG/plist: build-time artifacts — verified by shellcheck-
  level inspection and manual smoke (mount DMG, double-click a .md).
- Drop/open-urls/banner: GPUI shell, manual smoke per repo convention.

## Out of scope

Sparkle self-updating, tab-session restore, sample-content generator,
overlay tutorials, Windows/Linux installers.
